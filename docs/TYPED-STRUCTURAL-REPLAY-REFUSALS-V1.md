# Typed structural replay refusals v1

Four private structural error families carry sealed data: repeated/unknown status
ExpressionId, noncontiguous slot index, and repeated StorageId. Shared immutable
identity handles and Copy indices preserve the original subject without rendering
inner text or the detailed function prefix. These receipts confer no admission,
lookup, current-source, or replay authority.

The selected and ordinary structural cores retain their original reservation,
insertion, lookup, mutation and first-error order. The paid scalar/lexical drivers
select the typed error policy. Existing earlier inventory, status-construction,
current-member and capacity refusals retain their original order and owned channel.
A typed atom does not cause an earlier full-driver failure to be skipped.

Preparation retains the first engine receipt and transfers its existing caller-paid
fixed report. Capacity Diagnostics retain their already-paid backing. Legacy
Diagnostic adapters render the exact detailed SPX-H006 text; that compatibility
boundary remains explicitly unfunded by the fixed report. Other semantic families
and successful whole-engine allocation inequalities remain open.

The owning tests distinguish receipt construction, legacy rendering, and a held
Session structural subphase. The latter observes acquisition through first error,
fixed-report transfer and Drop on the same reservation. Its constructor baseline
is measured separately; the additional unique storage-key debit is independently
derived from the existing B-tree layout policy. Zero additional allowance and
one-short controls preserve the first capacity receipt; exact allowance reaches
the typed structural failure. This is not full-driver candidate acceptance or
whole-pipeline physical funding evidence. Full-driver current-member error parity
and ordinary/selected detailed status errors remain separate controls.
