# Cleanup epsilon closure sharing v1

Status: authored compiler optimization; qualification pending. Owner: issue #830.

The ordinary factored canonical receiver may share a completed immutable child closure for exactly one expanded automaton shape: the node is not the sink, has no labeled moves, and has exactly one epsilon edge. The child lookup stays at the original first child-lookup position; missing-child diagnostics keep their complete original identity. Every other shape executes the complete a33 general producer, including duplicate-edge weight accumulation, sink membership, own labeled moves, empty maps and checked arithmetic. No graph rewrite, schema change, ID reordering or new source admission occurs.

The original producer starts an empty map for this shape. Each unique child key is inserted once with initial weight zero, so `0 + routes` cannot overflow a u64. The resulting map equals the child's complete ordered map, including every weight. Sharing its existing Rc therefore preserves closure contents and all downstream weighted subset IDs/signatures. The full a33 producer is independently compiled in `before_alias.rs`, with only lexical module/test adapters and test-only read wrappers; its complete original source is archived. The earlier before-index and before-sharing producers remain independent.

The original cursor walk is untouched. The receiving helper iterates every child entry and issues its original separate one-unit `factored closure route addition` request, then the original `len + 1` `factored skeleton closure` request. Requests are not aggregated or discounted. Each old logical work frontier, phase and complete selected diagnostic remains the same when physical admission suffices. Physical costs deliberately differ: absent map nodes and a fresh Rc allocation are not constructed or debited. There are no refunds, quota resets, cap/fuel changes or borrowed oracle allowances.

After all old work requests, immediately before clone/publication, the helper pays the exact callee Rc initializer, caller receiving Rc local and actual Result<Rc,Diagnostic> carrier through the same existing byte owner. The child Rc allocation and whole map backing stay owned and fully paid in the child's memo entry; Rc::clone creates no new backing. These are explicit source carriers, not a claim about ABI spill slots or optimizer-chosen machine-stack copies. The existing authenticated Memo insertion pays its ordinary receiving directory/chunk/control costs. LegacyUnobserved remains explicitly unpriced as before; this is no new owner or admission route.

The existing id entry and closure entry authenticate the exact function, budget address and current ledger before cache access. The helper consumes the borrowed child from that same authenticated closure, authenticates the same payer with a zero request before cloning, and never exports a generic cache. One local Canonicalizer and the same borrowed receivers span the ordinary factored comparison's two roots. Helper failure marks the memo failed without a payer requery, formatting or replacement of the actual first diagnostic. Existing getters decline subsequent acquisitions after failure. This does not revoke previously returned Rc values or Rust borrows; all retained values still follow their normal final-owner Drop.

Qualification must retain complete old/current maps, IDs/signatures, duplicate/mixed/sink shapes, long chains ending in multi-entry closures, diamonds/shared children/repeated roots, checked weighted overflow, every small-fixture work frontier, independent exact/short/zero byte limits, foreign/restored/stale custody and whole constructor-to-last-Drop observations. Test-only census derives eligibility and would-be copied entries from the actual produced fixture/memo and reports them outside the observer; it adds no production instrumentation or permission. Those fixture counts do not establish current application frequency.

Actual allocations, cumulative reservations and peak live backing are reported separately. Source proof and pending assertions establish neither an application fit nor a universal saving or exclusive cause of a previous frontier. Unchanged application/backend owners and current actual producer receipts remain authoritative.
