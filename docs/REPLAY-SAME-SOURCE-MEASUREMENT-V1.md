# Same-source replay constructor measurements v1

Status: focused owners authored; no measurements have been executed or gains
established by this change. This is bounded evidence for OPT #749/#750, not a
full replay or application execution qualification.

The owning lib-test namespace is
`cleanup_plan::replay::physical_storage::representative_measurements::`.
Two ordinary deterministic bodies verify exact borrowed node order, work and
backing one-short refusal, and a 64-statement independently checked source. A
third, explicitly ignored body loads the actual Catalog, ShiftSim, and Catalog
normalizer projects. It copies their committed source bytes; Catalog/ShiftSim
use their existing authenticated generator derive/replay route and install the
unchanged committed command body. It records SHA256 bindings for the original
and effective source sets. Neither application logic, limits, corpus, manifest
profile nor original files are rewritten. Preparation failures remain visible
as diagnostics, without a fabricated snapshot or narrowed replay context.

On each admitted full-project HIR snapshot, the owner compares four crossed
constructors: indexed children/exact growth, saved cursor/exact growth, indexed
children/geometric growth, saved cursor/geometric growth. The saved indexed
Block/Match prefix algorithm counts actual examined statements/arms. All
requires, body, ensures, monomorphic functions and instantiated functions retain
authored left-to-right node order. Closures' actual children remain visited.
An independent pointer-by-pointer preorder comparison is outside measurement.
A refused constructor reports its completed prefix and precise work, depth or
backing refusal; equal complete inventories are asserted only when both complete.

These constructors build a borrowed expression inventory, not the entire
cleanup replay state machine. They grant no admission authority. Work is actual
constructor visits/prefix inspections/cursor advances, not a substituted full
ReplayBudget debit or program fuel. The fixed depth carrier is the same on all
four paths. Limits remain 32,000,000 constructor operations, cache depth, and
64 MiB cumulative requested backing. The old growth control reserves each full
exact replacement before allocation; the new route invokes the production
geometric reservation helper. Nested payload is only a borrowed pointer, so it
requires no cloned ID/type backing discount.

Each strategy reports seven alternating ordinary-allocator wall samples and
min/median/max, without any speed inequality gate. Refused versus completed
phases perform different amounts of work: their wall times must not be called
an equal-work speedup. A separate thread-bound
allocator pass independently records actual requested Layout allocations,
replacement overlap highwater, and zero live backing after Drop. Its counters
and verdict must match the wall pass. Stack reservation is reported separately
from observed heap layouts. Fixed observer storage, authenticated snapshot,
source loading/generation and output formatting are outside the paired samples.
The ordinary allocator may use realloc internally; the observer deliberately
retains old and replacement backing through the copy. Neither observation is
RSS or malloc usable size. Preparation wall time is separately labeled, and
this owner does not execute the application or report live agent metrics.

The same preparation captures completed semantic cached (mode 7) static
forecast components: raw/runtime structural and String costs, exact expression
counts, existing literal storage absence, pre/post mode substitution, identity
occurrence and carrier bounds, retained total, generic instances and transient
imports, plus the immutable original mode-7 fixed-bundle formula as a diagnostic
control (overflow is explicit, never a usable bound). This is a cfg(test)-only fixed-storage observer, with no new budgets,
refunds or changed verdicts. It keeps the last 256 completed forecasts and
reports discarded prefixes/oversized paths explicitly. The same fixed ring records
private type authority index requests (declaration count, actual node bound,
requested bytes and enclosing remainder) before the unchanged reservation.
A requested index is not a completed allocation or an authority grant. It never treats a partial
module sum as an admitted application. Literal absence records expose an
investigation seam; they do not implement a constructor discount or prove that
Catalog/ShiftSim/normalizer fit the unchanged 64 MiB contract.
