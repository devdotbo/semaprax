Status: source checkpoint; current-head owning execution qualification pending.

Audience: compiler contributors and reviewers.

This private source batch changes comparison and scratch carriers only. Complete
validation, source/HIR identity checks, ownership/loan/cleanup semantics, both
backend type carriers, and the literal 67,108,864-byte builder limit remain.
Qualification is pending the root's combined focused run; no Cargo, build or test

The observed owning logs at 58ee1bcad show ten refusals in HIR final validation;
selected05 refused earlier in HIR canonical cleanup plans. The receipts identify
the authenticated stage, not the exact inner allocation. This change does not
claim those applications now fit or assign measured savings to those receipts.

* Native import container comparisons borrow the exact current index's Result
  and Option IDs and actual argument trees. They compare all structural/type
  bytes without building discarded result trees. The ordinary allocating
  `ResolvedImportResultKind::value_type` remains complete and unchanged.
* Generic type validation holds eight pending frames inline, with the complete
  Vec spill route for larger inputs. Push/pop order and every type, signature,
  arity and semantic-facts check remain. Eight is a storage optimization, never
  an admission bound. The complete previous receiving body and eager validator
  remain independent references, with original literals retained.
* Array and scalar Function flag misses project the original exact scalar
  branches without constructing full layout facts and classifier scratch.
  Exact cache lookup still precedes projection, including forged cached flags.
  All other misses use the full original classifier.
* Nominal fact-directory preparation borrows exact ordered-cache keys instead
  of constructing discarded identity strings. Eligibility, held identities,
  ordering, metadata Vec/Arc construction and exact reservation stay intact.
  The full previous paid constructor remains an independent reference.
* The paid flag receiver calls its existing payer's zero-byte authentication and
  sticky check before known-leaf or exact-cache results. The complete
  `Storage<P>` constructor, reservation and miss classifier live in a separate
  non-inlined receiving function and initialize only on the miss/fallback route.
  This removes a charge only when that specific object is not constructed.
  Both complete original wrapper and classifier remain. No paid allowance,
  refund, caller verdict, depth bound or allocator estimate is introduced.

The stack carrier separation is an explicit source ownership change, not a
measurement of emitted machine stack usage. Ordinary validator inline scratch
and bounded canonical-key comparison retain their existing pure/storage
contract; this is not a claim of complete final-validator physical funding.
Owned cache keys, genuine substituted type trees and all miss-path allocations
retain their original constructors/payment boundaries. Existing hostile stale
facts, forged IDs and backend gates remain full.

The authored controls compare complete original/current carriers and diagnostic
objects, exact cache precedence, original paid metadata entries, actual
allocation-through-Drop, unbounded Vec spill ordering and same-owner sticky
refusal. They include all result kinds, missing compiler IDs, foreign IDs,
invalid callable arity and arguments, cache misses, zero/exact/one-short/floor
boundaries and retries. Exact selectors and complete baseline/current source
bytes are in `evidence/hir-final-validation-scratch/`. The existing application
selectors remain unchanged. Full quality gates are excluded by user instruction.
