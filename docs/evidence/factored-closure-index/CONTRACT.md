# Private numeric closure memo v1

Status: source-authored; owning runtime qualification pending.

The ordinary shared canonical receiver preserves the complete epsilon-closure walk, checked route-weight arithmetic, cycle selection, weighted signature algebra and all logical work charges. Only its outer numeric-key memo changes from per-entry BTree nodes to lazy eight-slot chunks. Inner closure maps and Rc payloads remain unchanged. `before_index.rs` preserves the complete old producer body; only its lexical parent import, original test-hook import, and registration of its original test module differ. All original tests remain registered on the current receiver, with the old receiver available independently. The older pre-sharing receiver is untouched.

One ordinary `factored::equivalent` invocation constructs one local Canonicalizer, calls `id` for its HIR and plan roots with the same borrowed function and budget, then drops it before either borrow ends. No memo or read view escapes. `id` authenticates before even a cached state hit; `closure` authenticates before reads; insertion authenticates separately. Function and budget pointers are compared, never dereferenced. They are custody checks for this private call lifetime, not a portable identity or permission to reuse a receiver after replacing either referent in place. No additional production caller is admitted by this change.

First failure is sticky. An unproven foreign budget is never queried or formatted into a report: mismatch returns the allocation-free private six-field empty H006 diagnostic. Restoring the invocation cannot reactivate the memo. Failed getters serve no view; retained storage is disposed normally. Every fallible closure operation returns immediately on error, so its final root getter cannot turn a selected failure into `Ok(None)`.

Exact new source layout terms:

- Once, activation pays one `size_of<Memo<T>>()` inline receiver and the separately named `size_of<Option<Binding>>()` initializer moved into its existing binding slot. The containing `Canonicalizer::new` has no carrier charge: there is no outer payment to subtract or duplicate. Its allocation-free inert setup precedes activation; activation precedes all new payload allocation/publication. `Option<Binding>` already contains its Binding, so there is no additional nested Binding fee.
- Each authenticated paying call acquires its actual `size_of<Result<(), Diagnostic>>()` authorization receipt before returning it. This is separate from the one-time receiver payment; no nonexistent Result type is charged.
- Each new chunk pays `2 * size_of<[Option<T>; 8]>() + size_of<Box<[Option<T>; 8]>>()`: one explicitly named source array initializer, one simultaneous heap array, and one explicitly named Box pointer. The directory's Option<Box> receiving slot is already in its backing fee. Rust moves of these values do not create additional independently owned source objects. This is the explicit source carrier model, not a claim about ABI spill slots or optimizer-chosen machine-stack copies.
- Directory growth uses the existing `reserve_vec` protocol: it pays the complete derived replacement target, calls `try_reserve_exact` on that same Vec, checks its capacity equals that target, and only then calls `resize_with`. The old backing remains fully charged. Sparse/growth controls check actual capacity against that producer's derived target.

`pays_allocations` is fixed by the ReplayBudget's constructor; no later payer reassignment exists. Explicit LegacyUnobserved keeps positive allocation charges skipped, including refusal-text bootstrap. `ClassifierLedger::capture/current` clone/compare the existing ACTIVE Rc; they do not create a ledger. Legacy array/Vec helpers retain their previous ordinary allocator route. Production keys are existing indices into the same finite, already constructed automaton nodes Vec; an arbitrary unrepresentable usize index is not an admitted legacy source key.

A high first key requires `key / 8 + 1` directory slots including gaps, plus one chunk. Sparse, short or small cases can therefore cost more than the old map. Caps and logical work allowances stay unchanged, while actual byte refusal frontiers deliberately follow the new producer. No universal saving, application fit, exclusive prior failure cause, oracle-budget waiver, or current qualification claim follows from this source change. The whole old/current semantic, diagnostic, overflow/cycle, work, exact/short/zero, physical payment and last-Drop owners remain required.
