# Held status identity insertion index

Status: component verification; full owning compiler and CI gates pending.

Audience: compiler maintainers and reviewers.

The completion matrix's compiler-capacity row retains the 64 MiB workspace
construction limit and the 32,000,000-unit program-wide replay limit. Ordinary
retained status insertion previously performed a complete expression/lane
comparison at each AVL search step. A privately held compressed bit index now
finds the same AVL insertion coordinates for ordinary sets of at least 256
status sources. Smaller sets, selected retention and leased oracle accounts
keep the complete retained search. The threshold selects storage, not schema,
source admission, a larger allowance or a fallback after refusal.

Each expression byte has a marker bit; the end symbol is the complete, closed
lane discriminator. This preserves expression-then-lane ordering for empty
expressions, prefixes, embedded zero bytes and UTF-8. Internal nodes retain
only byte/mask and construction coordinates. A leaf refers to an unchanged
full key in the original directory. Each lookup still compares that complete
key, including its lane. An exhaustive lane mapping makes a new lane require
an explicit code update.

The first walk records its paid path. The first differing byte/lane locates the
insertion subtree on that path; extremal leaves supply its exact predecessor
and successor. Those adjacent AVL keys identify the same empty child as the
original full-key search. The original AVL insertion links, rotations, sorted
iteration and global held-prefix comparison remain. The index neither parses
identifier syntax nor hashes keys, grants authority or survives the exclusive
held builder. Existing subject, current-row and ledger authentication precedes
its use; source order and duplicate handling stay unchanged.

Index nodes and reusable path backing are reserved before growth. New search,
call/return, scalar and node-construction layouts are paid before use, and new
bit/path bookkeeping is charged on the original work ledger. A refusal remains
sticky; there is no refund or retry through an unfunded receiver. This trades
additional actual heap backing for fewer comparison frames and lower cumulative
reservation in the measured larger cases. It does not claim reduced RSS or
identical physical allocation for indexed sets.

All eight original directory controls remain intact. New controls compare every
AVL link against the independent complete-key comparator across lanes, UTF-8,
prefixes, empty strings, NUL and duplicates; exercise exact/short/zero/floor
frontiers and final Drop; reject reuse after work or foreign-ledger refusal;
and retain a 16,000-key success and an unchanged-cap fallback SPX-H006 regression.
Complete current modules and all thirteen owning bodies were exercised on Rust
1.88 and 1.98 with a fixture-only HIR factory/non-status carrier adapter, actual
budget payment/work/refusal bodies, the frozen budget component, real System
allocation observation and actual physical storage. This is component evidence,
not full compiler or backend qualification. Local processes retain the 200 MiB
RAM guard; no full local compiler build was run.

Three complete predecessor sources have full hashes and exact inverses. Earlier
custody packets compose them without replacing original archives or assertions.
The original production-core retry, whole STD-08/native/installed fixtures,
current report pins, all full quality gates and Lean remain required.

The twenty-one complete source-custody assertion bodies, three digest controls,
the complete core authority assertion, source-reader gates, documentation gates,
release reconciliation contracts, focused Clippy and changed-file Rustfmt/diff
checks passed. Both omitted-marker and omitted-lane counterexamples compiled
and failed the full AVL equality control. The old comparison, held search,
common-prefix and owner authentication functions are byte-exact; all original
owning tests and source-controller bytes remain complete prefixes of their files.
