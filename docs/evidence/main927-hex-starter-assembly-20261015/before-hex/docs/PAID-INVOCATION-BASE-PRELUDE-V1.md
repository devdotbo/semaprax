# Paid Invocation Base Prelude v1

Audience: compiler contributors, tool authors, and reviewers.

Status: source-only producer and borrowed overlay, pending ordinary resolver integration and executable qualification. Tracking: issue #828. Nominal payload ownership depends on #827. This contract does not supersede Workspace Graph Prelude Forecast Accounting v1 or change graph/cache schemas, public identities, byte/work limits, or supported execution profiles.

## Ownership and construction

One successful live invocation may construct one immutable base Option/Result bundle and lend it to multiple module-local declaration indexes. No process-global cache, OnceLock, source-name/use filter, lazy unpaid materialization, or borrowed source-lifetime extension is admitted. The existing `prelude::base_schema::BASE` is the sole production schema; Option then Result order, all case/field/parameter ordinals, compiler identity origins, persistent IDs and default source spans remain exact. The producer creates all nine declaration descriptors and both complete resolved types unconditionally, including unused declarations. Extended/private/runtime prelude selection stays with its existing owner.

The invocation supplies an explicit `Payer` for cumulative requested bytes and work. Both methods retain the invocation's first sticky refusal, including subsequent zero requests. Failure returns a small typed value with no dynamic diagnostic text. A public report may render only at its established funded boundary. A successful bundle is published only after every input and the final shared owner have been paid and constructed; refusal drops the partial local owner and exposes no bundle.

For a vector of n elements T the request is exactly checked `Layout::array::<T>(n).size()` before `try_reserve_exact`; unexpected capacity is refused rather than silently grown/repaired. String backing uses the same paid u8 vector, copies UTF-8 and validates before conversion without another backing allocation. Each new persistent identity uses the existing paid identity producer and its real carrier/layout rule. Its funded identity references may then be cloned without duplicate backing. Each parameter sequence and complete outer variant-case sequence uses #827's borrowed-Vec funded acquisition; nested case fields remain the canonical Vec inside that case sequence. All nominal control blocks, simultaneous initializer and iterative disposal scratch remain #827's responsibility, explicitly paid before acquisition. No per-case Arc is introduced.

Before producer work or backing allocation, acquisition separately precharges the actual `size_of::<Contents>()` initializer, `size_of::<BasePreludeBundle>()` receiver and `size_of::<Result<BasePreludeBundle,Failure<E>>>()` result carrier with checked sums. These coexist with the final owner and are not silently treated as free. The invocation bundle's final Arc allocation is then precharged as `Layout::new::<repr(C) { strong: usize, weak: usize, value: Contents }>().size()`, including both reference counters and actual Vec headers. Already paid Vec/string/identity/nominal backing is not charged again as newly constructed backing in that carrier. This is an actual requested-allocation model, not RSS or a retained-forecast discount. Physical measurements must separately confirm every requested allocation is covered.

The real initial Index owner currently supplies only bytes. `fixed_work::FixedSchemaPayer` is a separate draft for a finite compiler-schema work counter, with its paid inline carrier and exact const metadata operation bound specified in [Fixed Base Prelude Producer Work v1](FIXED-BASE-PRELUDE-PRODUCER-WORK-V1.md). It grants no replay work or source authority. ROOT accepted its private activation conditions; actual root integration and qualification remain required, and no unconditional successful work bridge is permitted.

## Borrowed overlay and work

An overlay borrows the base owner and one existing local index. It never builds merged maps or clones nominal HIR. Base declaration/type/case/field/parameter lookups return original borrowed payloads; local misses consult the existing local owner's facts. Declaration traversal merges sorted persistent-ID orders deterministically, giving the base entry on a duplicate ID; this creates no source admission exception. The ordinary verifier continues to reject forged compiler identities. Base spelling precedence remains the existing prelude precedence; parser-only overlap controls do not admit shadow declarations.

Within the explicitly work-paid overlay, every actual string-key comparison receives a checked input-length work charge before comparison. Directory sorting is fallible insertion sorting over the already paid descriptor vector, without hidden sorting scratch. Local compatibility lookups conservatively charge their full key inventory before the existing coordinate validation. Explicit retain charges a zero-byte sticky check and one work unit before Arc clone. Borrowed queries and retained leases must have zero actual heap acquisition; repeated module use does not silently rebuild an index or type payload. Failure of an iterator produces one typed failure and then ends, preserving the invocation's first selected refusal.

Existing infallible Index queries require a separate fixed-base borrowed seam: `declarations_slice`, `types_slice`, declaration-by-text and type/case/field/parameter lookup return the same immutable facts without allocation or an invented work account. These bounded queries neither debit nor reset any ledger and are explicitly unmetered. A source receiver with an existing work payer must use the fallible overlay or debit its own unchanged bound before calling these views. Raw views make no source admission decision; compiler identity spelling alone grants no authority. The independent old-index control compares complete facts and observes zero actual query allocation.

## Returned HIR and logical export integration seams

After the ordinary root authenticates base-source semantics at its original early point, `materialize_type(id, reserve)` returns None for a foreign ID and cannot substitute a compiler owner. A matching base type prepays its fresh name backing and actual String/type/Option/Result receiving layouts on the caller's existing byte callback before allocation. It returns the exact old ID/name/span/parameter/case order while cloning only already-funded nominal views. The materialized type may outlive the invocation bundle: its parameter/case payload leases remain real owners. No AST base reconstruction or duplicated case/field payload is needed by this helper. It invents no work ledger and does not claim to fund the caller's complete Resolver/HIR output vectors.

`declaration_iteration(local)` merges the sorted raw local map and sorted base descriptors with base precedence on duplicate IDs, returning an ExactSizeIterator whose remaining length counts local keys plus base keys absent from the actual local map. It must not call a fallback-enabled Index getter to compute that count. Generic `merge_by_key` supports other logical map exports with the same already-sorted input and duplicate rules, no temporary collection and no work authority. Root equality/codec integration must compare/export full logical facts, and must not normalize malformed decoded local facts or replace them with trusted base merely from an ID spelling. Those root adaptations remain separately owned by #827.

## Lifetime and disposal

The final invocation owner outlives all borrowed overlays. An explicit paid retain may extend the same owner without allocating another control block. Pure compatibility `Clone` also shares already-owned immutable backing for existing infallible Index clones, matching DeclarationId and NominalPayload cloning. It neither authenticates sticky state nor pays a new receiving Index/HIR carrier; qualified acquisition routes retain their existing whole-receiver reservations and use paid retain/zero-request checks for a new invocation view. Pure query/Clone behavior cannot grant source or budget authority. The last owner drops descriptor/type vectors iteratively; #827's final nominal owner uses its preacquired iterative disposal scratch. Base field types are scalar type-parameter references. No fresh queue, recursive nominal traversal, source read, physical finalizer or report allocation is permitted during disposal. Partial-construction refusal follows the same owned cleanup path and preserves first failure.

## Qualification boundary

The independent original AST constructors remain in a cfg(test) module with their old constructor bodies; the original index constructor remains a distinct legacy full-copy route under #827, with an independently retained pre-change entry point for full-oracle qualification. Controls compare complete type/declaration payloads, IDs, origins, order and every lookup, then address identity and real allocation/drop receipts across two module overlays and an explicit retained lease. Exact bytes/work, one short, zero, every acquisition-site refusal and sticky subsequent use must preserve no leaked owner. New modules are initially unregistered and must not be described as executable support until integrated, compiled and run by the owning qualification lane.

Before replacing ordinary constructors or reducing any forecast, the integrated route must qualify complete old/current HIR, diagnostics, graph JSON/digests, cache replay and native/Wasm behavior; unconditional unused/overlap selection; physical requested allocations, retained backing, highwater, final-owner iterative Drop, error paths and all relevant application controls. The current corrected prelude term P remains unchanged until that replacement is genuine and physically qualified. Repeated constructor savings are cumulative allocation/work evidence; they do not by themselves prove lower peak retention. No application gain or exclusive-cause claim follows from this source-only packet.
