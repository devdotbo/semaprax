# Plan branch continuation capacity

Status: focused component checks passed; full owning cases and CI pending.

Audience: compiler maintainers and reviewers.

Ordinary ActiveBuilder plan branch copies can reserve less unused growth
capacity. A bounded read-only plan probe counts an upper bound on observations
through the target's linear continuation. It accepts either a terminal exit or
one subsequent fork whose final branch has a complete terminal suffix. It
counts all transitions and every goto conservatively. The resulting backing
holds the current branch observation, the entire continuation and that later
final branch's terminal observations. Earlier branches leave their source
unchanged; the existing final-prefix transfer therefore still fits. Published
observations remain flat, in exactly their original order.

The complete original clone census, clone work event and materialization event
remain. Selected and other payers use the complete old receiver. Missing
references, singleton or further forks, nonterminal exits, exhausted walks,
overflow or insufficient avoided backing retain the old growth capacity.
Traversal is bounded by the already existing prefix length, and exhaustion
only disables this optimization. No admission cap, work quota, refund, metadata
repair or backend permission is introduced. Saved backing must pay the complete
new probe layout before selection; every new backing byte and the probe fee are
reserved before allocation.

The unmodified generic `for_push` remains independently compiled. A new owning
96-step checked-arithmetic case compares every full path, both work accounts,
materialization counts and Drop with the complete independent old enumerator.
A test-only counter requires use of the new paid constructor. A typed three-block
shape receiver also checks exact future capacity and final transfer eligibility
at widths 42, 64 and 128, complete input identities, both work accounts, Drop,
and zero/one-short/exact refusal frontiers; a further fork and missing edge keep
the old route. The earlier final transfer and all original clone tests remain
unchanged.

Focused Rust 1.88 and 1.98 probes execute the full actual helper, bounded probe,
budget methods and Rc/Vec clone census with a real System allocation observer.
Explicit HIR/observation payload and common-push adapters cover 182 combinations
of prefix lengths and future shapes; 27 select smaller paid copies. They check
complete reference identities, exact future capacity, continued eligibility of
the next final transfer, both work accounts, exact/one-short/zero limits,
reserved floors, sticky refusals and full Drop. The width-42 next-fork fixture
uses a 258-byte probe layout: reservations fall from 2,870 to 2,816 bytes and
observed allocation from 2,870 to 2,558, with skeleton work four in both routes.
Those adapted fixture totals include input setup and the existing refusal
buffer; they are not a whole compiler bill, service admission result or process
RSS measurement. Every compiler child uses the unchanged 200 MiB aggregate cap.

The current-head STD-08 run also exposed a reserved `result` local after the
String-vector fixtures reached further validation. It becomes `outcome` for the
same encode result and match, and a stable diagnostic test retains SPX-S109 and
SPX-T201. The earlier fixture source control restores all five site changes to
the complete original module, preserving every old case, byte value, limit,
independent serializer, backend and diagnostic assertion.

Five complete predecessor sources have full hashes and exact inverses. Older
custody packets compose those inverses, while their archives, original source
assertions and static formatting registry remain unchanged. These packets
carry no runtime authority. The original STD-08 corpus, native and installed
journeys, low-stack run, all full quality gates and Lean remain required. The
8c08 unit-heavy run also exposed a status-directory work refusal;
that independent issue is not qualified by these clone probes.
