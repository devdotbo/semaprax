# Ordinary replay receiving ABI v1

This source candidate owns OPT #892. It has not been compiled, run, benchmarked,
qualified for adoption, or shown to improve an application. The existing
[RFC 0003](RFC-0003-CLEANUP-AND-RESOURCE-ABI.md) replay contract and
[workspace graph](WORKSPACE-SEMANTIC-GRAPH-V1.md) limits remain unchanged.

## Boundary

The actual ordinary HIR skeleton caller acquires its receiving bank at the
immediate-old `with_index` constructor-controls frontier, after the original
builder/refusal-text and clone-cursor preflights. It owns one inline complete
Diagnostic destination and one inline prepared inventory. Five direct output
producers preserve renewal, moving strings, condition reads, lexical presence,
and owner order. Indexed renewal omission and conditional owner discovery are
the original conditions. The bank conservatively prepays all five possible
producer argument/result packets, as the immediate constructor did; unused
packets do not earn a credit. One reserve callback and one captured ledger span
these producers. Every original callback `current()` check still precedes its
original reservation.

The helpers' generic failure parameter is the inline unit refusal token. The
actual budget/refusal producers expand lexically into the caller's Diagnostic
destination. They do not call a returning Diagnostic budget method and then
adapt its Result. The original generic returning collectors, `with_index`, and
budget methods remain compiled. The actual selected branch and leased oracle
constructor keep their previous route.

The actual retained ordinary cross-phase caller and certified-row continuation
own one full error destination and borrowed query-output slot per retained
lookup activation. The two returning/receiving Diagnostic Results disappear
from the new query methods. Query argument/formal loans are paid at the literal
caller, before invocation; every inherited scratch/query charge and work event
remains. Absent, present noncall and present call remain distinct, and a hit
points into the immutable arena rather than scratch or the error destination.

The query guard is the unchanged successful HeldPrefix insertion or frozen
status-directory guard immediately before the query. Its exact function,
budget and current-ledger checks, exclusive Session budget loan, immutable
arena/function loans and closed continuation span the query. No callback or
ACTIVE switch occurs in that interval. There was no `current()` call inside
the immediate-old query to remove. New slot function/budget association is
checked before any primitive can spend. This private protocol grants no fresh
schema, source, ID, proof or report authority. Selected-family migration remains
#781 and public report publication remains #825.

A filled error destination is sticky; retries neither replace its six fields
nor consume its String again. The first failure moves out only when the owning
invocation returns. Initial builder/cursor/acquisition failures remain on the
original earlier returning boundary. Zero reservation retains authentication
without refusal-text bootstrap. Detached unobserved compatibility keeps its
original allocating renderer; this is not a newly funded admission route.

## Storage, lifetime and accounting

`Prepared` drops partially collected inventories in reverse legacy local
construction order. Successful field moves preserve SkeletonWork's original
field order. New fields do not attach a verdict to HIR or widen a cached proof.
The query error owner is explicitly dropped before program-dependent
transition callbacks; output borrows end at their last immutable use. Existing
helper-index and continuation storage remain the sole program owners.

`receiving::acquisition_bytes` prices the complete inline Prepared and Failure,
one possible full terminal Diagnostic/Some/Cow initializer, actual/formal
prepare and collector frames, exact callback capture/reborrow fields, captured
ledger, small funded results and callback references. It does not assume a
constant target layout. The query invoice prices its actual/formal self,
expression, output and failure loans and bool result, plus literal caller
reborrows. Every query pays its complete invoice anew. Scratch acquisition and
all old work/caps remain unchanged.

For a complete successful composition, let C be reached ordinary setup owners,
M retained lookup owners, and Ns/Ne actual status/edge queries. Let B0 be the
literal complete immediate constructor-controls expression, B1 the new setup
invoice, L the new query-loan invoice, E the full error/output-owner acquisition,
and D the old Result<Option<&Option<CallFact>>,Diagnostic> layout. The expected
paid-byte change, before any unrelated route difference, is:

`old - new = C*(B0-B1) + (Ns+Ne)*(2*D-L) - M*E`.

All terms use actual target types. No original callback, collector backing,
work unit or retained scratch is credited twice. Cold setup can regress; only
a measured complete corpus can determine the sign. A refused prefix reports
only reached counters and actual paid bytes; it is not a whole-app census or
future-work saving. Test-only counters mark overflow incomplete and carry no
authority. No app admission, net saving or token claim follows from source.

## Executable owner controls (authored, unrun)

The existing unit harness owns the candidate; no top-level binary is added.
Complete immediate ordinary, HIR caller and certified lookup bodies are
independently compiled controls. Original budget and two-Result lookup methods
remain available. Original tests are retained rather than redirected to a
partial receiver.

- `ordinary_receiving::tests::`: complete collector outputs, ordered inventories,
  work counters, exact/one-short/zero physical limits, sticky first Diagnostic,
  foreign source/budget rejection and complete allocation-through-Drop.
- `arena::retained::into_tests::`: 0/1/many UTF8/NUL and equal-spelling distinct
  backing, hit/miss/noncall/call pointer identity, every old work cut and all six
  fields, exact/short/zero/floor, sticky and unwind/Drop.
- `case_certified::lookup_tests::receiving::`: complete immediate ordinary
  program composition, real setup/owner/query counts, unchanged 64 MiB gate,
  independent 0/1/32/64-row cost observations, exact/short/zero, original-error
  precedence, malformed status cases, foreign helper index and immutability.
  The dense-success net-gain assertion is a future adoption gate, not evidence.

Current source-custody dependency unions must include every new child, both
complete old caller children, and their owning registrations before any
qualification. The external immutable packet supplies whole base sources and
exact inverse patches. Source-custody integration is deliberately separate
from this implementation lane.
